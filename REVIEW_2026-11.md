# Code review and break-it testing, November 2026

Written 21 Nov 2026. Scope: `index.html`, `js/`, `css/` as they stood at commit `18636f3` (1 Nov 2026).

## How it was done

1. An independent reviewer read every file in full without being told what to look for, and decoded all 179
   recordings to check its claims.
2. Each finding was then reproduced in a browser on the old code before anything was changed, and checked again on the
   new code. The old code ran from an untouched copy beside the new one, on the same data.
3. Break-it tests: `test/page.html` runs the real page on recordings that no export would produce (`test/synth.js`
   writes them in the browser): a file cut in half, zero frames, one frame, no muscles, no foot bones, a missing array,
   a not-a-number value, a file that is not there, seven runners, two frame rates in one scene, a run that ends early,
   and a real run repeated to two minutes.
4. Speed: `test/bench.html` times the per-frame work on the five recordings of pair 1 (600 calls, 5 repeats, the
   median). It was run twice on each version, old and new in turn.

One limit of the test set-up: the browser pane used for the tests was not on screen, and a browser stops animation
frames there. The page was therefore driven by a 16 ms timer (`?raf=timer`), and no frames-per-second figure is
reported. The bench does not depend on animation frames.

## Speed and memory, measured

| Measure | Old | New |
|---|---|---|
| Per-frame work on the processor, 5 sprinters with muscles (`update`) | 0.58 and 0.74 ms | 0.70 and 0.62 ms |
| A whole frame including the graphics card | 4.01 and 3.79 ms | 3.87 and 4.09 ms |
| Placing the labels, per frame | 0.021 and 0.033 ms | 0.005 and 0.008 ms |
| Memory one recording keeps | 3.48 MB | 2.33 MB |
| Memory after visiting all 12 pairs, device off and on | 84 recordings, about 292 MB (84 × 3.48, computed) | 30 recordings, 69.9 MB (measured) |
| Sent to the graphics card per frame | 521.6 KB | 312.9 KB; 33.4 KB with muscles off |

Read plainly: **the page did not get faster per frame**; the two runs of each version differ more from each other
than old differs from new, and a frame was already about 4 ms. What changed is how much the page holds and moves:
a third less memory per recording, a ceiling on the recordings kept, and 40 % less data sent to the graphics card
each frame. The label step is four times cheaper but was already small.

## Changed without a browser demonstration

These follow from reading the code; the test pane could not show them. Each is a few lines.

- The drawing resolution follows the screen's pixel ratio when the browser zoom changes or the window moves to
  another monitor (before: fixed at page load).
- Time spent in a hidden tab is no longer counted as slow frames (before: it could step the resolution down for good).
- Videos stop when the Films tab is left for a 3D tab (before: only when left for Results or About).
- A browser too old for the page (before Chrome 89, Firefox 113, Safari 16.4) gets a sentence instead of a spinner.
- Space or a double click while the first-visit card is open closes the card as well as starting the race.
- Footprints: the stage draws at most 600, and the lanes took them in order, so on a recording of more than about
  two and a half minutes the first lane would use them all. Each lane now keeps its own latest ones. The two-minute
  test is too short to show the difference.

## Found and left

- **19 recordings in `data/runs` are not used by the page** (3.8 MB): the `p1_*_f2*` push repeats and three early
  pair-1 files. Four of them (`p1_{twin,mix,brake,dev}_f2_s5`) have a header the page cannot read (`NaN` written into
  JSON by the exporter for runs of 30 frames or fewer). Nothing points at them; removing them is the owner's call.
  The exporter (`web_pack.py`) should write `null` there.
- **A recording longer than the track** (the two-minute test) runs off the 190 m of track into empty sky, and the
  stand view backs away to keep runners 900 m apart in frame. No real recording is longer than 10 s.
- **On a phone** the page keeps drawing while the 3D view is scrolled out of sight, and the timeline's time marks
  are crowded on a 375-pixel screen.
- **Slow-frame detection** still cannot tell a slow graphics card from a display that refreshes 30 times a second:
  on such a display the resolution steps down once playing starts. It needs a measure of the frame's real cost.
- **The stage has room for six runners.** More are cut off rather than drawn; raising the limit means more lanes
  in the camera views.

## Second pass: a fresh reviewer on the fixes themselves

A second reviewer, who had not seen the first review, read the fix commit for anything it broke. It traced the
graphics-card upload change through three.js and ran the new file checks against all 179 recordings: no regression in
what worked before, and no recording wrongly refused. It found six smaller faults in the new code, all fixed and
checked in the browser:

- A recording that lists fewer bones than the page has (only a test file today) drew the missing bones in an old pose;
  they are now not drawn for that runner (scale 0 in the test, 0.75 to 0.94 for the runner that has the bone).
- With the selected sprinter hidden, the Close view showed an empty track; it now shows the first sprinter on show.
- With a failed 3D start and a link to `#films`, the Films page stayed empty; it is now built (6 videos).
- The 3D controls could be used in the half second before the 3D view exists (an error, and the Muscles box out of
  step); they are switched off until it exists.
- A file of 0 or 1 bytes gave an unclear message; a `nov` runner without a description printed "undefined".

## Running the tests again

Serve the folder (`python -m http.server`) and open:

- `test/bench.html` for the timings (JSON on the page and in `window.benchResult`).
- `test/page.html?case=<name>` for a break-it case: `mixedfps`, `early`, `refearly`, `long`, `missing`, `allmissing`,
  `nomuscle`, `nofeet`, `oneframe`, `zero`, `nan`, `truncated`, `noarray`, `seven`. Add `&raf=timer` in a background
  tab, `&fail=bones.bin` to make a download fail, `&debug` to get the page's state in `window.sp3d`.
